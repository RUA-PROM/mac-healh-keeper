## 1. 概要

### 1.1 システム概要

Swift の `shell()`/`notify()` ほかシェル実行を、文字列補間ではなく `Process` の `arguments` 配列で構築し、コマンド注入耐性を高める。残す文字列実行はエスケープを徹底する。振る舞いは不変。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| 引数配列化 | `/bin/bash -c "<文字列>"` ではなく実行ファイル + 引数配列で起動すること |
| コマンド注入 | 補間値に仕込んだ文字列が任意コマンドとして実行される脆弱性 |

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 注入耐性のあるシェル実行

- **As a** 開発者 / 利用者
- **I want to** シェル実行が引数配列で構築される
- **So that** 補間値に特殊文字が入っても任意コマンドが実行されない

**受け入れ基準**:

- `Process` + `arguments` 配列で実行する経路がある。
- 文字列補間で `bash -c` にコマンドを組み立てる箇所が排除/最小化されている。

#### ストーリー 2: 通知の安全なエスケープ

- **As a** 利用者
- **I want to** 通知メッセージに引用符等が含まれても壊れない
- **So that** 通知が確実に表示され注入されない

**受け入れ基準**:

- 引用符・バックスラッシュ・改行を含むメッセージでも安全に表示される。

### 2.2 BDD ユースケース

#### ユースケース 1: 引数配列による実行

シェル実行を引数配列で行う。

**シナリオ 1: 特殊文字を含む引数**

```gherkin
Feature: 引数配列による実行
  Scenario: 引数に ; や $() を含んでも追加コマンドが実行されない
    Given 引数に "; rm -rf x" や "$(touch y)" を含む入力
    When 引数配列で外部コマンドを実行する
    Then 入力は単一引数として扱われ追加コマンドは実行されない
```

#### ユースケース 2: 通知のエスケープ

`notify()` が特殊文字を安全に扱う。

**シナリオ 1: 引用符を含むメッセージ**

```gherkin
Feature: 通知のエスケープ
  Scenario: ダブルクォートを含むメッセージでも通知が壊れない
    Given メッセージに " と \\ を含む
    When notify を呼ぶ
    Then 通知が表示され注入も破損も起きない
```

#### ユースケース 3: ジョブ状態取得の安全化

`launchctl list` 連携で label を安全に扱う。

**シナリオ 1: label を引数として渡す**

```gherkin
Feature: ジョブ状態取得の安全化
  Scenario: label をシェル補間せず引数/フィルタで扱う
    Given ジョブ label を含む状態取得
    When 引数配列または安全なフィルタで取得する
    Then 補間によるコマンド組み立てが無く結果は従来と同じ
```

### 2.3 ビジネスルール

- シェル実行経路は Infra（サブ B の ShellRunner）に集約する。
- 文字列実行を残す場合は対象・理由・エスケープ方法を記録する。
- 振る舞いは不変（サブ A のテストで固定して実施するのが望ましい）。

## 3. 非機能要件

### 3.1 パフォーマンス要件

- 実行方式変更で体感速度を悪化させない。

### 3.2 セキュリティ要件

- 補間値が任意コマンド実行に至らない（注入耐性）。

### 3.3 ユーザビリティ要件

- 通知文言・ジョブ操作の結果を変えない。

### 3.4 可用性要件

- 実行失敗時のフォールバック挙動を従来と同等に保つ。

---

## 4. 外部インターフェース要件

### 4.1 API 要件

- `ShellRunner` の実行 I/F（実行ファイル + 引数配列）を 02 で定義し、本サブはそれに準拠する。

### 4.2 データ形式要件

- 標準出力の取り回し（trim 等）を従来と一致させる。
