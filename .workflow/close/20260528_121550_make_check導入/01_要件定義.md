# 要件定義書: make check 導入による検証集約

**プロジェクト名**: make check 導入による検証集約
**作成日**: 2026 年 05 月 28 日
**最終更新**: 2026 年 05 月 28 日

> **重要**: 要件の変更・追加があれば即座に反映する。

---

## 1. 概要

### 1.1 システム概要

`make check` ターゲットを Makefile に追加し、lint（shellcheck）/ format 検査（shfmt, swift-format）/ Swift lint（swiftlint）/ 循環 source 検出 / セキュリティ静的 grep / `make test` を 1 コマンドで連続実行する。各ステップの終了コードを集約し、いずれかが失敗したら全体を非 0 終了する。未導入の任意ツールは WARN を出してスキップする。

### 1.2 用語集

| 用語             | 説明                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| make check       | 本 issue で追加する検証集約ターゲット                                 |
| 循環 source 検出 | シェルの `source` / `.` 依存グラフに循環が無いことを静的検査する処理 |
| WARN             | 未導入の任意ツールを検出した際の警告。終了コードには影響しない        |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 開発者がローカルで一気通貫の検証を行う

- **As a** 開発者
- **I want to** `make check` 1 コマンドで lint・format・循環・セキュリティ・テストを実行
- **So that** PR 提出前に網羅的に検証できる

**受け入れ基準**:

- `make check` を実行すると、定義された全ステップが順次実行される。
- 全成功時は `==> all checks passed` 相当の標識を出して 0 終了する。
- いずれか失敗時は失敗ステップ名を表示して非 0 終了する。

#### ストーリー 2: 任意ツールが未導入でも CI を止めない

- **As a** 開発者
- **I want to** shfmt / swift-format / swiftlint が未導入の環境でも `make check` を完走させたい
- **So that** ツール導入待ちで全体検証がブロックされない

**受け入れ基準**:

- 該当ツールが PATH に無ければ「SKIP（理由）」を標準エラーに出力し、当該ステップは成功扱いとする。
- shellcheck は **必須** とし、不在時は失敗扱い（または強い WARN）とする。

### 2.2 BDD ユースケース

#### ユースケース 1: make check の正常実行

**シナリオ 1: 全ツールが揃っていて違反も無い**

```gherkin
Given shellcheck, shfmt, swift-format, swiftlint, bats が PATH にある
And  リポジトリのコードに lint/format/循環/セキュリティ違反が無い
When make check を実行する
Then 各ステップが順に走り
And  終了コード 0 で完了する
And  最終行に「all checks passed」相当のメッセージが出力される
```

**シナリオ 2: 任意ツール未導入だが違反なし**

```gherkin
Given shellcheck と shellcheck だけが PATH にある
And  shfmt / swift-format / swiftlint が PATH に無い
When make check を実行する
Then 未導入ツールの行は「SKIP」と表示される
And  shellcheck / 循環検出 / セキュリティ grep / make test は実行される
And  終了コード 0 で完了する
```

**シナリオ 3: shellcheck 違反検出**

```gherkin
Given scripts/bin/foo.sh に shellcheck 違反がある
When make check を実行する
Then shellcheck の出力で違反が表示される
And  終了コードは非 0 になる
```

**シナリオ 4: 循環 source 検出**

```gherkin
Given scripts/lib/a.sh が scripts/lib/b.sh を source し
And  scripts/lib/b.sh が scripts/lib/a.sh を source する
When make check を実行する
Then 循環検出ステップが循環パスを出力する
And  終了コードは非 0 になる
```

**シナリオ 5: セキュリティ静的 grep**

```gherkin
Given scripts/ 配下のファイルに `eval "$untrusted"` 相当の危険パターンが含まれる
When make check を実行する
Then セキュリティ grep が該当行を file:line 形式で出力する
And  終了コードは非 0 になる
```

**シナリオ 6: test 失敗の連鎖**

```gherkin
Given lint・循環・セキュリティはすべてパスする
And  make test が失敗する
When make check を実行する
Then test 失敗が表示される
And  終了コードは非 0 になる
And  「some checks failed」相当のサマリが出る
```

## 3. 非機能要件

### 3.1 性能

- ローカルで lint〜セキュリティ grep までの実行時間 10 秒以内（テスト除く）。

### 3.2 セキュリティ

- 検出対象パターン（最低限）:
  - 秘密情報: `AKIA[0-9A-Z]{16}` (AWS Access Key), `password\s*=\s*['"][^'"]+['"]`, `token\s*=\s*['"][^'"]+['"]` 等
  - 危険: `eval\s+`, `rm\s+-rf\s+\$`, `curl[^|]*\|\s*sh`, `wget[^|]*\|\s*sh`
- 検出はベストエフォート。誤検出は exclude リストで除外可能とする。

### 3.3 互換性

- macOS（Darwin）/ bash 3.2 / zsh で動作。
- GNU 拡張（GNU grep の `-P` 等）に依存しない実装にする。

### 3.4 保守性

- 検証スクリプトは `scripts/lint/` 配下に分離。Makefile は薄く呼ぶだけ。

---

## 4. 制約条件

- shfmt / swift-format / swiftlint は本 issue では自動導入しない。README に手順を追記するに留める。
- 既存の lint 違反が大量に検出される可能性。最低限、現状コードで `make check` を緑にすることを優先し、必要なら exclude ルールを追加する。
