# T9 棚卸し結果（make check 現状コード適用）

**実施日**: 2026-05-28 13:20 JST

## 1. shellcheck（必須・実装直後の結果）

### 1.1 当初の状況

`shellcheck -x` を素のまま当てた場合、以下の警告が大量に発生し、`make check` が即赤になる状態だった:

- **SC1091（info）**: `Not following: <path>` — 大量。`$ROOT_DIR` / `$_LOG_SH_DIR` などの動的パスを shellcheck が解決できないことが原因。`-x` を付けても動的パスは追えないため避けられない。
- **SC2034（warning）**: 未使用に見える変数（実際は source 先で参照される）。
  - `scripts/config/thresholds.sh` の `THRESHOLD_*` / `MHK_*` 系（9 個）
  - `scripts/bin/monitor.sh` の `COOLDOWN_FILE`
- **SC1090（warning）**: `scripts/test/metrics_test.sh:173` の動的 source（`$METRICS_SH`）。
- **SC2012（info）**: `install.sh:90` の `ls` 使用（find 推奨）。
- **SC2016（info）**: `scripts/test/log_rotate_test.sh:142` single quote 内に `$` を含む（with_lock の引数として意図的）。
- **SC2162（info）**: `uninstall.sh:49` `read` without `-r`。

### 1.2 取った対応

設計書（02_設計 §3.3）の「`-e SC1091`（外部 source 警告抑止）等は最小限」と委譲制約の「重大な lint 違反は別 issue 化を提案、軽微修正に留める」を踏まえ、以下に整理:

- **`run-shellcheck.sh` に `--severity=warning` を追加**: info 級の SC1091 / SC2012 / SC2016 / SC2162 を非 0 化対象から外す。これは「大量の info で `make check` が常時赤」という現状コードの状態を、warning 以上のみフェイルとする最小限の調整で抜け出すための措置。
- **`scripts/config/thresholds.sh` 先頭に `# shellcheck disable=SC2034` を追加**: 本ファイルは「他スクリプトから source されて参照される設定」という性質上、定義側からは未使用に見えるのが正しい。
- **`scripts/bin/monitor.sh:21` の `COOLDOWN_FILE` 定義行に `# shellcheck disable=SC2034`**: 直後に source される `notification_cooldown.sh` の `should_notify` が暗黙参照する変数で、export していないため shellcheck からは未使用に見える。
- **`scripts/test/metrics_test.sh:173` の動的 source に `# shellcheck source=../lib/metrics.sh` ディレクティブを追加**: SC1090 の正規対処。

### 1.3 別 issue 提案（本 issue では未対応）

- **info 級警告の本格対応**: SC2012（install.sh `ls`→`find` 化）/ SC2162（`read -r` 化）/ SC2016（with_lock の意図明示・別関数化）など、現コードの軽微改善は別 issue で扱うのが妥当。
- **shellcheck の severity を `info` に戻して info も検出対象にする**: 上記の info 級対応が一通り済んだ後に検討する。
- **`-e SC1091` を付ける選択肢**: 今回は採用しなかった（`--severity=warning` で info 全般を抑止しており、SC1091 単独で抑止する積極理由は薄い）。将来的に warning レベルに上げて SC1091 が出始めたら、その時点で `-e SC1091` 化を検討する。

## 2. 循環 source 検出

- 現状コードのエッジは以下のとおりで、すべて単方向（`bin/*` → `lib/*`, `test/*` → `bin/*` / `lib/*`）。
  - `scripts/bin/*.sh` → `scripts/lib/{log,notify,metrics}.sh`, `scripts/config/thresholds.sh`, `scripts/bin/notification_cooldown.sh`
  - `scripts/test/*.sh` → `scripts/lib/*`, `scripts/bin/notification_cooldown.sh`
- **循環なし**。誤検出もなし。
- 検出ロジックの妥当性確認:
  - 一時ファイル `scripts/test/__cycle_a.sh` ↔ `__cycle_b.sh` を作って実行 → `CYCLE: ... -> __cycle_b.sh -> __cycle_a.sh -> __cycle_b.sh` を検出して非 0 終了。OK。
- ロジック上の補足:
  - `$_LOG_SH_DIR` のような独自変数を含む source 行はスキップ扱い（解析対象外）。これにより誤検出を防ぐが、検出漏れの可能性はある。本 issue では「`$ROOT_DIR` / `$SCRIPT_DIR` の 2 系統に限定して正規化」とし、それ以外は別 issue でも追加検討する余地あり（今は実害なし）。
