### 2.3 バージョン形式の判断

`grep` で過去履歴を確認した結果：

- `src/Info.plist` の `CFBundleVersion`: `1.2`（2 桁）。
- git commit メッセージ: `Initial commit: Mac Health Keeper v1.0`、`feat: メニューバー UI とメトリクス/ジョブ制御の改修 (v1.2)`、`docs: ... 仕様書に反映 (v1.2.0)`（混在）。
- 仕様書 `docs/README.md::更新履歴`: `v1.0.0` → `v1.1.0` → `v1.2.0` → `v1.3.0`（3 桁）。

→ **Info.plist は既存 2 桁形式 `1.2` に揃え `1.3` を採用**。仕様書バージョン `v1.3.0`（3 桁）とは独立概念として扱う（同期はするが、形式は別）。

### 2.4 バージョン正本ルールの明文化結果

`.agents/spec/04_仕様更新ルール.md` に以下 2 セクションを追記：

- **§アプリバージョンの正本**: アプリバージョンの正本は `src/Info.plist` の `CFBundleVersion` / `CFBundleShortVersionString`。docs / Swift コード上のリテラルは追従する従属情報。形式は 2 桁。
- **§バージョン更新時の必須手順**: ①Info.plist 更新 → ②連動コードリテラル更新（`src/MacHealth.swift::showAbout`）→ ③連動 docs 更新（G012 / ディレクトリ構成）→ ④仕様書バージョンと「最終更新」を必要に応じて更新 → ⑤`docs/00_review/` にリリース記録。

`docs/` 配下ではなく `.agents/spec/` 配下を選んだ理由：

- 既存の `04_仕様更新ルール.md` がドキュメント運用ルールの一次情報になっている。
- バージョン管理ルールは「仕様更新ルール」の延長として一元配置するのが自然。
- `docs/` は仕様（成果物）の一次情報、`.agents/spec/` はメタ規約という分担が既に確立している。

## 5. 残課題

- About アラート文言を実行時に `Bundle.main.infoDictionary?["CFBundleShortVersionString"]` で動的取得することで「Swift リテラル更新漏れ」を構造的に防ぐリファクタは、本 issue 範囲外。フォロー候補として `docs/00_review/20260529_094618_review.md` または別 issue で追跡。
- `docs/02_画面設計/README.md::G012` が「`informativeText` のリテラルそのもの」を記載しているため、将来 Bundle 動的取得化した場合は G012 の表記も「`Bundle.main.infoDictionary[CFBundleShortVersionString]` を末尾に表示」のような表現に切り替える必要がある。
