# 要件定義書: メトリクス非表示修正

**プロジェクト名**: Mac Health Keeper / メトリクス非表示修正
**作成日**: 2026 年 05 月 29 日
**最終更新**: 2026 年 05 月 29 日

---

## 1. 概要

### 1.1 システム概要

`MetricsCollector` がインストール先の `metrics.sh` を呼び出して値を取得し、`MenuModel` がメニュー表示文字列を組み立てる。インストール先に `metrics.sh` が無い場合の振る舞いを明示的に「警告ログ + 警告ラベル」へ統一し、ユーザーが原因に気付ける状態を保証する。

### 1.2 用語集

| 用語              | 説明                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| `metricsShPath`   | `~/.local/bin/mac-health/lib/metrics.sh` の絶対パス（AppDelegate 定数）|
| 5 指標            | 負荷／空き／スワップ／Uptime／Compressed                              |
| 警告ラベル        | メニュー上に表示する「メトリクス取得不可」相当の固定文字列            |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: メトリクスを再び見たい

- **As a** Mac Health Keeper を常用するユーザー
- **I want to** メニューを開いたら現在の負荷・空きメモリ・スワップ等が表示されてほしい
- **So that** Mac の健康状態を一目で把握できる

**受け入れ基準**:

- `./install.sh` または `make install` 完了後にアプリを起動した状態で、メニュー上の 5 指標がいずれも値付きで表示される。
- 60 秒周期で値が更新される（手動 Refresh でも更新される）。

#### ストーリー 2: 取れない原因が見える

- **As a** 同上のユーザー
- **I want to** メトリクスが取れない場合に「再インストールが必要」を知らせてほしい
- **So that** サイレント空欄で困らない

**受け入れ基準**:

- `metricsShPath` が存在しない状態でアプリを起動した場合、メニュー先頭付近に「⚠ メトリクス取得不可：再インストールしてください」相当の警告ラベルが表示される。
- 同条件で stderr に `[MetricsCollector] metrics.sh not found: <path>` の警告が 1 回出力される。

#### ストーリー 3: 開発者の運用一元化

- **As a** Mac Health Keeper の開発者
- **I want to** `make build` でビルドし、`make install` でインストールしたい
- **So that** scripts と app の整合性が崩れる運用ミスを避けられる

**受け入れ基準**:

- `make build` で `src/` と `Sources/MacHealthKit/` をまとめてコンパイルし、`./build/MacHealth` 等の成果物が出る（あるいは `install.sh` 同等の swiftc 経路）。
- `make install` で `./install.sh` が呼ばれる。
- `make check` は緑のまま維持される。

### 2.2 BDD ユースケース

> 本節は **回帰検知可能なシナリオ集**。 §2.2.4 以降は本 issue フォローアップ（テスト不十分の是正）で追加。
> 自動テスト経路は `swift run MacHealthCheck`（XCTest 非依存・常時実行）と `scripts/test/install_metrics_smoke_test.sh`（make test-shell から実行）。

#### ユースケース 1: メトリクス収集の正常系

**シナリオ 1: metrics.sh が配置されている**

```gherkin
Feature: メトリクス収集
  Scenario: metrics.sh が存在する
    Given ~/.local/bin/mac-health/lib/metrics.sh が存在する
    And   MacHealth.app が起動している
    When  60 秒経過してメトリクスが収集される
    Then  MetricsSnapshot.loadAvg / swapUsed / memoryFreePct が空文字以外の値を持つ
    And   メニュー上にそれぞれの値が表示される
    And   MetricsSnapshot.collectorErrors は空である
```

#### ユースケース 2: メトリクス収集の異常系

**シナリオ 1: metrics.sh が無い**

```gherkin
Feature: メトリクス収集
  Scenario: metrics.sh が未配置
    Given ~/.local/bin/mac-health/lib/metrics.sh が存在しない
    When  AppDelegate.applicationDidFinishLaunching が走る
    Then  stderr に "metrics.sh not found" を含む警告が 1 回出る
    And   メニュー先頭付近に "⚠ メトリクス取得不可" のラベルが追加される
    And   負荷・空き・スワップは現状どおり "—" 表示で空文字落ちしない
```

**シナリオ 1: make install が install.sh を呼ぶ**

```gherkin
Feature: 開発者向け運用導線
  Scenario: make install を実行する
    Given リポジトリのルートにいる
    When  `make install` を実行する
    Then  `./install.sh` が呼ばれる
    And   `~/.local/bin/mac-health/lib/metrics.sh` がコピーされている
```

**シナリオ 2: make build がビルドする**

#### ユースケース 4: 不在検知ロジックの純粋関数化（テスト可能化）

> 振る舞いの本体（不在 → エラー伝播 → stderr → メニューバナー）を `MetricsCollectorPolicy.decide(exists:path:previouslyWarned:)` という純粋関数に集約し、`swift run MacHealthCheck` で常時検証する。回帰検知の核となる。

**シナリオ 1: exists=true（配置済み）→ エラー追加なし・stderr 出力なし・warned フラグはリセットされる**

```gherkin
Feature: MetricsCollectorPolicy.decide
  Scenario: 配置済み（exists=true）
    Given metricsShPath が存在する
    And   前回までに警告未出力（previouslyWarned=false）
    When  decide(exists:true, path:..., previouslyWarned:false) を呼ぶ
    Then  collectorErrorsToAppend は []
    And   stderrLineToWrite は nil
    And   nextWarnedAboutMissingScript は false
```

**シナリオ 2: exists=false / previouslyWarned=false（初回不在）→ collectorErrors 1 件追加・stderr 1 行・フラグは true へ**

```gherkin
Feature: MetricsCollectorPolicy.decide
  Scenario: 初回の不在検知
    Given metricsShPath が存在しない
    And   前回までに警告未出力（previouslyWarned=false）
    When  decide(exists:false, path:"/x/y/metrics.sh", previouslyWarned:false) を呼ぶ
    Then  collectorErrorsToAppend == ["metrics.sh not found: /x/y/metrics.sh （./install.sh を再実行してください）"]
    And   stderrLineToWrite == "[MetricsCollector] metrics.sh not found: /x/y/metrics.sh\n"
    And   nextWarnedAboutMissingScript == true
```

**シナリオ 3: exists=false / previouslyWarned=true（不在 2 回目以降）→ collectorErrors は積み続けるが stderr は出さない（スパム抑止）**

```gherkin
Feature: MetricsCollectorPolicy.decide
  Scenario: 不在中の 2 回目以降
    Given metricsShPath が存在しない
    And   既に stderr へ警告済（previouslyWarned=true）
    When  decide(exists:false, path:..., previouslyWarned:true) を呼ぶ
    Then  collectorErrorsToAppend.count == 1（メニューバナーは継続表示）
    And   stderrLineToWrite == nil（stderr のスパムは抑止）
    And   nextWarnedAboutMissingScript == true
```

**シナリオ 4: 復旧系：不在 → 配置済みに戻ったとき、warned フラグは false にリセットされる**

```gherkin
Feature: MetricsCollectorPolicy.decide
  Scenario: 復旧
    Given 直前まで metricsShPath が存在しなかった（previouslyWarned=true）
    When  decide(exists:true, path:..., previouslyWarned:true) を呼ぶ
    Then  collectorErrorsToAppend == []
    And   stderrLineToWrite == nil
    And   nextWarnedAboutMissingScript == false  # 次回再度不在になったとき、再度 stderr 警告を 1 度だけ出せる
```

**シナリオ 5: 警告フォーマットの境界**

```gherkin
Feature: MetricsCollectorPolicy 警告書式
  Scenario: パス以外に補間値を含まない固定書式
    Given path = "/abs/path/to/metrics.sh"
    When  missingScriptCollectorError(path:) と missingScriptStderrLine(path:) を呼ぶ
    Then  collectorError == "metrics.sh not found: /abs/path/to/metrics.sh （./install.sh を再実行してください）"
    And   stderrLine == "[MetricsCollector] metrics.sh not found: /abs/path/to/metrics.sh\n"
    And   どちらもパス以外の補間値を含まない（注入面なし）
```

| ユースケース / シナリオ                       | 自動テスト経路                                                         | 実行コマンド                          |
| --------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------- |
| UC1-S1（正常系）                              | `swift run MacHealthCheck`（UC: MenuModel collectorErrors 空のケース） | `make test-swift-purecore` または `make check` |
| UC2-S1（不在時の異常系・メニュー / stderr）  | `swift run MacHealthCheck`（UC: MetricsCollectorPolicy / MenuModel）  | 同上                                  |
| UC4-S1〜S5（純粋関数 decide / 警告書式）     | `swift run MacHealthCheck`                                            | 同上                                  |
| UC5-S1, S2（MetricsParser フォールバック）   | `swift run MacHealthCheck`                                            | 同上                                  |
| UC6-S1〜S3（install / metrics.sh smoke）     | `scripts/test/install_metrics_smoke_test.sh`                          | `make test-shell` または `make check` |

> 既存 `Tests/MacHealthKitTests/MenuModelTests.swift` の XCTest は **XCTest 搭載環境向けの追加経路**として残す（重複ではなく、二重検知の安全網）。Command Line Tools のみの環境では SKIP されるが、`swift run MacHealthCheck` 経路が常に走り回帰を検知する。

### 2.4 ビジネスルール

- 警告ラベルは `MenuModel` の純粋関数として組み立てる（テスト対象に乗せる）。
- 警告ラベルの文言は固定（補間値なし）。
- 不在検知ロジック（`metrics.sh` の存在判定 → エラー伝播・stderr 警告・スパム抑止）は
  `MetricsCollectorPolicy.decide(exists:path:previouslyWarned:)` という純粋関数に閉じる。
  Imperative Shell（`MetricsCollector`）は I/O（`FileManager.fileExists` と `fputs(stderr)`）のみ担う。
- 自動テストは「環境依存で SKIP されない経路」を必ず 1 本以上持つ。
  `swift run MacHealthCheck`（CLI testrunner）と `scripts/test/install_metrics_smoke_test.sh`
  を `make check` の必須経路とし、XCTest 搭載環境のみで走る `Tests/MacHealthKitTests/` は
  二重検知の安全網として残す。

## 3. 非機能要件

### 3.1 パフォーマンス要件

- 60 秒周期の収集に影響なし。`FileManager.fileExists(atPath:)` を 1 回呼ぶオーバーヘッドのみ。

### 3.2 セキュリティ要件

- 既存の「補間値を流入させない引数配列起動」原則を維持。

### 3.3 ユーザビリティ要件

- 警告ラベルは「⚠」を冒頭に付け、続いて「再インストールしてください」の旨を日本語で表示する。

### 3.4 可用性要件

- `metrics.sh` 不在時もアプリはクラッシュせず、ジョブ制御・ログメニュー等の他機能は動作する。

---

## 4. 外部インターフェース要件

### 4.1 API 要件

- `metrics.sh <metric>` の引数契約（load/swap/free/compressed/uptime_days/uptime_hours/docker）は不変。

### 4.2 データ形式要件

- `MetricsSnapshot` に `collectorErrors: [String]`（オプション・既定 `[]`）を追加。
