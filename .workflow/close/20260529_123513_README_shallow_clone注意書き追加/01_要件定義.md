# 要件定義書: README に shallow clone 注意書きを追加

**プロジェクト名**: Mac Health Keeper / README shallow clone 注意書き
**作成日**: 2026 年 05 月 29 日
**最終更新**: 2026 年 05 月 29 日

---

## 1. 概要

### 1.1 システム概要

A 案で `git describe` 由来の自動 stamp を採用したため、shallow clone 環境では `0.0.0-DEV` fallback になる。README で利用者に明示する。

### 1.2 用語集

| 用語 | 説明 |
|------|------|
| shallow clone | `git clone --depth=N` による浅いクローン。tag 履歴が含まれない場合がある |
| fallback 値 | `git describe` が tag を見つけられないときの `0.0.0-DEV` 等の代替値 |
| install 手順節 | README.md 内の「インストール」「Install」相当の節 |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 新規ユーザーの導入摩擦を減らしたい

- **As a** Mac Health Keeper の新規ユーザー
- **I want to** README の install 手順に shallow clone の注意書きがあること
- **So that** 知らずに `0.0.0-DEV` 版を導入することを防ぎたい

**受け入れ基準**:

- README の install 手順節に注意書きが 1〜2 行で記載されている
- 「shallow clone 不可」または「`git fetch --tags --unshallow` が必要」の意味が伝わる

#### ストーリー 2: 開発者が再現確認したい

- **As a** 保守担当
- **I want to** 注意書きに従わずに shallow clone した場合の fallback 動作を実機で再現確認したい
- **So that** ドキュメントの根拠を持っておく

**受け入れ基準**:

- `git clone --depth=1` → `./install.sh` で fallback 値が入る
- `git fetch --tags --unshallow` 後の install で正しい stamp 値が入る

### 2.2 BDD ユースケース

#### UC1: README 注意書きの存在

**シナリオ UC1-S1: README に注意書きがある**

```gherkin
Feature: README 注意書き
  Scenario: install 手順節に shallow clone 注意書きがある
    Given README.md を開く
    When install 手順節を読む
    Then shallow clone（--depth=1）に関する注意書きが 1 文以上ある
    And  `git fetch --tags --unshallow` または `MACHEALTH_AUTO_UNSHALLOW` のいずれかに言及している
```

#### UC2: shallow clone での fallback 再現（参考観点）

**シナリオ UC2-S1: --depth=1 で 0.0.0-DEV fallback**

```gherkin
Feature: shallow clone fallback
  Scenario: --depth=1 clone 後の install で CFBundleVersion が fallback 値になる
    Given git clone --depth=1 でリポジトリを /tmp/test に複製
    When cd /tmp/test && ./install.sh を実行
    Then defaults read .../Info CFBundleVersion が 0.0.0-DEV または同等の fallback 値である
```

**シナリオ UC2-S2: --unshallow 後は正しい stamp**

```gherkin
Feature: shallow clone fallback
  Scenario: --unshallow 後の install で stamp 値が正しい
    Given /tmp/test で `git fetch --tags --unshallow` を実行
    When ./install.sh を再実行
    Then CFBundleVersion が `git describe --tags --always` と一致する
```

#### UC3: shallow_clone_guard.sh による検出と警告（**新機能・本 issue 中核**）

**シナリオ UC3-S1: 通常 clone では警告なし**

```gherkin
Feature: shallow_clone_guard 検出
  Scenario: 通常 clone（非 shallow）で guard を呼ぶと警告なし
    Given 通常 git clone されたローカルリポジトリ
    When  bash scripts/lib/shallow_clone_guard.sh "$repo" を実行
    Then  終了コード 0
    And   stderr に "shallow" の警告文が出ない
```

**シナリオ UC3-S2: shallow clone で警告 + 推奨手順を表示**

```gherkin
Feature: shallow_clone_guard 検出
  Scenario: shallow clone で警告と推奨手順が stderr に出る
    Given `git clone --depth=1` で複製したローカルリポジトリ
    When  bash scripts/lib/shallow_clone_guard.sh "$repo" を実行
    Then  終了コード 0（ビルド継続）
    And   stderr に "shallow clone detected" 等の警告が出る
    And   stderr に "git fetch --tags --unshallow" 推奨手順が出る
    And   stderr に "CFBundleVersion may fall back to 0.0.0-DEV" 等の影響説明が出る
```

**シナリオ UC3-S3: MACHEALTH_AUTO_UNSHALLOW=1 で自動回復**

```gherkin
Feature: shallow_clone_guard 自動回復
  Scenario: 環境変数 MACHEALTH_AUTO_UNSHALLOW=1 で auto unshallow
    Given shallow clone されたローカルリポジトリ
    And   MACHEALTH_AUTO_UNSHALLOW=1
    When  bash scripts/lib/shallow_clone_guard.sh "$repo" を実行
    Then  内部で `git fetch --tags --unshallow` が走る
    And   実行後 is_shallow_clone は false を返す
    And   stderr に "auto unshallow" 旨のログが出る
    And   終了コード 0
```

```gherkin
Feature: shallow_clone_guard 引数検査

    Given 引数なし
    When  bash scripts/lib/shallow_clone_guard.sh を実行

```

**シナリオ UC4-S2: .git 不在ディレクトリで警告 + 終了コード 0**

```gherkin
Feature: shallow_clone_guard ディレクトリ検査
  Scenario: .git を持たないディレクトリは shallow ではないと扱う
    Given .git ディレクトリを持たない一時ディレクトリ
    When  bash scripts/lib/shallow_clone_guard.sh "$dir" を実行
    Then  終了コード 0
    And   stderr に "not a git repository" 旨のスキップログが出る
    And   shallow 警告は出ない
```
