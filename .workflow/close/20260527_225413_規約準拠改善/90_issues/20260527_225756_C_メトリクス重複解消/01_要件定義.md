# 要件定義書: サブ C メトリクス取得ロジックの重複解消

**プロジェクト名**: サブ C メトリクス取得ロジックの重複解消
**作成日**: 2026 年 05 月 27 日
**最終更新**: 2026 年 05 月 27 日

> **重要**: **このドキュメントは常に更新**します。
>
> **用語**: [.agents/CONCEPTS.md §用語規約](../../../../.agents/CONCEPTS.md#用語規約) を参照。

---

## 1. 概要

### 1.1 システム概要

swap/compressed/load/pressure/uptime のメトリクス取得を `scripts/lib/metrics.sh` に集約し、`mac-health` と `monitor.sh`（および可能なら Swift 側）が単一の定義を参照するようにする。出力は不変。

### 1.2 用語集

| 用語 | 説明 |
| ---- | ---- |
| メトリクス | swap 使用量・圧縮メモリ・Load Avg・メモリ空き率・稼働時間 |
| 集約 | 重複実装を 1 箇所の関数に統合すること |

---

## 2. 機能要件

### 2.1 ユーザーストーリー

#### ストーリー 1: 単一参照源の確立

- **As a** 開発者
- **I want to** メトリクス取得を `scripts/lib/metrics.sh` の関数で一元化する
- **So that** 定義変更が 1 箇所で済み不整合が起きない

**受け入れ基準**:

- `metrics.sh` に swap/compressed/load/pressure/uptime の取得関数がある。
- `mac-health` と `monitor.sh` が `metrics.sh` を source して使う。

#### ストーリー 2: 出力の不変性

- **As a** 利用者
- **I want to** 集約後も表示・判定が以前と同じ
- **So that** 体感が変わらない

**受け入れ基準**:

- 同一環境で集約前後の値（単位・丸め）が一致する。

### 2.2 BDD ユースケース

#### ユースケース 1: メトリクス取得の集約

`metrics.sh` の関数が単一の取得結果を返す。

**シナリオ 1: swap 使用量の取得**

```gherkin
Feature: メトリクス取得の集約
  Scenario: metrics.sh の swap 関数が MB 整数を返す
    Given vm.swapusage が "used = 512.00M" を返す環境
    When metrics_swap_used_mb を呼ぶ
    Then 512 が返る
```

**シナリオ 2: 圧縮メモリの取得**

```gherkin
Feature: メトリクス取得の集約
  Scenario: metrics.sh の圧縮メモリ関数が GB を返す
    Given vm_stat の compressor ページ数が既知の環境
    When metrics_compressed_gb を呼ぶ
    Then ページ数×4096 を GB 換算した値が返る
```

#### ユースケース 2: 参照側の一致

`mac-health` と `monitor.sh` が同じ関数を使い値が一致する。

**シナリオ 1: 2 つの参照元で同値**

```gherkin
Feature: 参照側の一致
  Scenario: mac-health と monitor.sh が同じ swap 値を得る
    Given 同一環境で metrics.sh を source する
    When 双方が metrics_swap_used_mb を呼ぶ
    Then 同じ値を得る
```

### 2.3 ビジネスルール

- 丸め・単位（MB/GB/%）は集約前の挙動を踏襲する。02 で明文化する。
- `metrics.sh` は「メトリクス取得」の単一責務に閉じる。閾値判定・通知は含めない。
- 禁止命名（helpers/misc/common/utils）を使わない。

---

## 3. 非機能要件

### 3.1 パフォーマンス要件

- 集約による追加プロセス起動を最小化する。

### 3.2 セキュリティ要件

- 取得関数のコマンド構成も注入を意識する（詳細はサブ F）。

### 3.3 ユーザビリティ要件

- `mac-health` の status 表示書式を変えない。

### 3.4 可用性要件

- いずれかのコマンドが無い環境でも従来同様にフォールバック値を返す。

---

## 4. 外部インターフェース要件

### 4.1 API 要件

- `metrics.sh` の関数名・戻り値（標準出力）を契約として 02 で定義する。

### 4.2 データ形式要件

- 単位・キー名（swap=…MB, compressed=…GB 等）を維持する。

---

## 5. 制約事項

- Bash。`scripts/lib/metrics.sh` に配置。Swift 側の対応方針は 02 で決定。
