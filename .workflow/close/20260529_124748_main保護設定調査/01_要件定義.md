# 要件定義書: main ブランチ保護 Ruleset の適用

**作成日**: 2026 年 05 月 29 日
**最終更新**: 2026 年 05 月 29 日

> 00 要求定義の §6 を BDD として詳細化する。実装/検証は 03 / 04 で対応。

---

## 1. ユーザーストーリー

### US-1: 直 push を構造的に防ぐ

```
As a   solo dev (ADMIN)
I want main 保護 Ruleset を適用し、自分自身でも直 push できない状態を作る
So that 監査可能な変更履歴（PR 経由）と CI 通過の事前ゲートを担保したい
```

### US-2: solo dev でも自分で merge できる

```
As a   solo dev
I want approving review count を 0 にした PR rule を維持する
So that PR → CI 緑 → 自分で squash merge ができる
```

### US-3: 緊急時の脱出経路

```
As a   solo dev
I want Ruleset を UI/API から disable できる状態を保つ
So that 障害時に main を一時直せる（ただし通常運用ではしない）
```

---

## 2. BDD シナリオ

### UC1: 直 push 拒否

```gherkin
Feature: main 直 push の拒否
  Background:
    Given main ブランチに保護 Ruleset が enforcement: active で適用されている
    And   Ruleset の rules に "pull_request" が含まれている
    And   bypass_actors は空である

  Scenario: ADMIN が main へ空 commit を直 push する
    Given 開発者 adachi-tatsuru は ADMIN 権限を持つ
    And   ローカルで main をチェックアウトし `git commit --allow-empty` した
    When  `git push origin main` を実行する
    Then  push は失敗（exit code != 0）する
    And   stderr に "protected branch" または "pull request" を要求するエラーが出力される
    And   remote の main は更新されない
```

### UC2: PR 経由 merge（solo dev でも可）

```gherkin
Feature: PR 経由 merge の許可
  Background:
    Given main 保護 Ruleset の pull_request rule は required_approving_review_count: 0
    And   required_status_checks rule の context は "check"

  Scenario: solo dev が自分の PR を CI 緑後に squash merge する
    Given feature/* ブランチから main 向けの PR が作成されている
    And   PR の最新コミットに対する `check` ステータスが success
    When  `gh pr merge <番号> --squash --delete-branch` を実行する
    Then  PR は squash でマージされる
    And   feature ブランチは local/remote で削除される
    And   `--admin` フラグは使用されていない
```

### UC3: CI 失敗時の merge ブロック

```gherkin
Feature: CI 失敗 PR の merge ブロック
  Background:
    Given main 保護 Ruleset の required_status_checks rule の context は "check"
    And   strict_required_status_checks_policy: true

  Scenario: CI 失敗状態で merge を試行
    Given PR が作成され check ジョブが失敗（conclusion: failure）している
    When  PR の merge を試行する
    Then  GitHub は merge を拒否する
    And   `gh pr checks` で `check` の失敗が表示される
```

### UC4: force push / branch deletion 拒否

```gherkin
Feature: 履歴破壊操作の拒否
  Background:
    Given main 保護 Ruleset の rules に "non_fast_forward" が含まれる
    And   rules に "deletion" が含まれる
    And   rules に "required_linear_history" が含まれる

  Scenario A: force push が拒否される
    When  `git push --force origin main` を実行する
    Then  push は失敗する
    And   stderr に "non-fast-forward" 系のエラーが出る

  Scenario B: main 削除が拒否される
    When  `git push origin --delete main` を実行する
    Then  push は失敗する
    And   main ブランチは remote に残る

  Scenario C: merge commit が拒否される
    When  PR の merge 方式に "merge commit" を選ぶ
    Then  GitHub は merge を拒否する（linear history 違反）
    And   squash または rebase のみ受理される
```

## 4. 非機能要件の落とし込み

- **可用性**: PR rule の `required_approving_review_count: 0` を保つ（solo dev 必須）
- **監査性**: GitHub UI Settings → Rules → Rulesets で誰でも参照可能
- **可逆性**: ADMIN が `PATCH .../rulesets/{id}` で `enforcement` を `disabled` / `evaluate` に変更可能

---

## 5. 用語

- **Ruleset**: GitHub の新しいブランチ保護方式。classic branch protection の後継で、複数 rule を 1 オブジェクトにまとめて管理する。
- **bypass_actors**: Ruleset を回避できる actor（user / team / role）のリスト。空 = 誰も回避不可。
- **strict_required_status_checks_policy**: PR の HEAD が base ブランチの最新を取り込んでいる場合のみ merge 可能（"Require branches to be up to date"）。

以上。
