## 2. ロールバック手順

| 状況 | 対処 |
| --- | --- |
| Ruleset 適用後に想定外の merge 拒否 | `gh api -X PATCH .../rulesets/{id} -f enforcement=disabled` で一時停止 |
| Ruleset 設定値ミス | `gh api -X DELETE .../rulesets/{id}` で削除し、修正版を再適用 |
| PR が merge できない | CI 失敗の場合は CI ログ確認 → 修正コミット追加。Ruleset 起因の場合は §1 Step 5 で挙動再確認 |
| feature branch 作業中に main 直 push をうっかり試行 | Ruleset で remote 拒否されるので影響なし。ローカルで `git reset --soft HEAD~1` |

## 3. テスト観点

| 観点 | 種別 | 検証方法 |
| --- | --- | --- |
| Ruleset 適用済み | 構成 | `gh api .../rulesets` で `enforcement: active` |
| 直 push 拒否 | 統合 | 空 commit + `git push origin main` 失敗 |
| PR merge 成功 | 統合 | `gh pr merge --squash --delete-branch` 成功 |
| `check` context が merge gate | 構成 | Ruleset JSON の `required_status_checks` に `check` |
| force push 拒否 | 構成 | Ruleset JSON の `non_fast_forward` |
| deletion 拒否 | 構成 | Ruleset JSON の `deletion` |
| linear history | 構成 | Ruleset JSON の `required_linear_history` |
| 受け入れ基準ルール準拠 | 規約 | 04_review に実機検証エビデンスあり |

## 4. リスク・注意事項

- **`git push origin main` は本依頼の全工程で禁止**（feature branch + PR のみ）
- `dangerouslyDisableSandbox=true` 禁止
- `git add -A` / `git add .` / `--no-verify` / `--amend` / `--force` / `git reset --hard` 禁止
- `gh pr merge --admin` 禁止（bypass を使ってしまう）
- Ruleset の `bypass_actors` を空のまま運用
- memo プレフィックスは **必ずシステム時計から取得** (`TZ=Asia/Tokyo date +%Y%m%d_%H%M%S`)
