# 設計書: main ブランチ保護 Ruleset の適用

**作成日**: 2026 年 05 月 29 日
**最終更新**: 2026 年 05 月 29 日

---

## 1. 方式選定

### 1.1 候補比較

| 方式 | 概要 | 採否 | 理由 |
| --- | --- | --- | --- |
| Classic Branch Protection (`PUT /branches/{branch}/protection`) | 旧 API。`enforce_admins` で ADMIN バイパス制御 | **不採用** | 古い API で機能拡張が止まりつつある。`bypass_actors` の概念がなく ADMIN バイパスの管理が二択（true/false）のみ |
| **Repository Ruleset (`POST /repos/{repo}/rulesets`)** | 新方式。複数 rule を 1 オブジェクト・bypass_actors 明示 | **採用** | bypass 管理が明示的、複数ブランチ対象に拡張容易、GitHub の推奨方式 |
| Lock branch のみ | 一時的な全 push 凍結 | 不採用 | solo dev でも自分で merge できる必要があり、機能不足 |

### 1.2 採用方式の責務境界

- **GitHub Ruleset**: main への push 全般のゲート（PR 強制 / status check / 履歴整合性）
- **GitHub Actions (`check.yml`)**: PR の品質ゲート（lint / shellcheck / tests）
- **gh CLI**: 設定の宣言・確認・実機検証
- **本 issue サブエージェント**: 設定適用と検証ログ記録

## 2. Ruleset 仕様

### 2.1 メタ

- **name**: `main branch protection`
- **target**: `branch`
- **enforcement**: `active`
- **conditions.ref_name.include**: `["~DEFAULT_BRANCH"]`（main がデフォルトブランチ。リネームに追従）
- **conditions.ref_name.exclude**: `[]`
- **bypass_actors**: `[]`（**誰もバイパス不可**。ADMIN も含む）

### 2.2 Rules（適用順序は GitHub 側で評価）

| type | parameters | 意図 |
| --- | --- | --- |
| `pull_request` | `required_approving_review_count: 0`, `dismiss_stale_reviews_on_push: true`, `require_code_owner_review: false`, `require_last_push_approval: false`, `required_review_thread_resolution: false` | PR 経由必須。solo dev のため approve 数 0。push 後 stale review は dismiss |
| `required_status_checks` | `strict_required_status_checks_policy: true`, `required_status_checks: [{context: "check", integration_id: null}]` | CI `check` ジョブが緑でないと merge 不可。strict = base 最新追従必須 |
| `non_fast_forward` | — | force push 禁止 |
| `deletion` | — | main 削除禁止 |
| `required_linear_history` | — | merge commit 禁止（squash / rebase のみ）|

### 2.3 設定意図（solo dev 安全設計）

- `required_approving_review_count: 0`: solo dev のため自分自身の PR を自分で merge できる必要がある（approver なし）
- `bypass_actors: []`: ADMIN を含む誰もバイパス不可。緊急時は **Ruleset を一時 disable** する運用に統一（後述 §5）
- `dismiss_stale_reviews_on_push: true`: 将来 reviewer を追加した場合のために有効化
- `strict_required_status_checks_policy: true`: PR は base ブランチの最新を取り込んでいないと merge 不可

## 3. CI context 名の特定

`gh run list --limit 5 --json name,workflowName,headBranch` の結果（直近実行・main ブランチ）:

```json
{"conclusion":"success","databaseId":26616515349,"headBranch":"main","name":"check","workflowName":"check"}
```

→ **context 名は `check`**（`.github/workflows/check.yml` の `name: check` + `jobs.check` に由来）。

`gh api repos/RUA-PROM/mac-healh-keeper/commits/main/check-runs` でも `"name":"check"` を確認済み。Ruleset の `required_status_checks` に渡す context 名は **`check`** で確定。

## 4. API 呼び出し設計

### 4.1 適用

```bash
gh api -X POST repos/RUA-PROM/mac-healh-keeper/rulesets \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  --input - <<'JSON'
{
  "name": "main branch protection",
  "target": "branch",
  "enforcement": "active",
  "conditions": {
    "ref_name": {
      "include": ["~DEFAULT_BRANCH"],
      "exclude": []
    }
  },
  "bypass_actors": [],
  "rules": [
    {
      "type": "pull_request",
      "parameters": {
        "required_approving_review_count": 0,
        "dismiss_stale_reviews_on_push": true,
        "require_code_owner_review": false,
        "require_last_push_approval": false,
        "required_review_thread_resolution": false
      }
    },
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": true,
        "required_status_checks": [
          {"context": "check", "integration_id": null}
        ]
      }
    },
    {"type": "non_fast_forward"},
    {"type": "deletion"},
    {"type": "required_linear_history"}
  ]
}
JSON
```

応答は変数に受けて `id` / `enforcement` / `rules` を確認する。

### 4.2 確認

- `gh api repos/RUA-PROM/mac-healh-keeper/rulesets`（一覧）
- `gh api repos/RUA-PROM/mac-healh-keeper/rulesets/{id}`（詳細）
- `gh api repos/RUA-PROM/mac-healh-keeper/rules/branches/main`（main に効く rule の集約結果）

### 4.3 緊急時の disable / 削除

```bash
# 一時 disable
gh api -X PATCH repos/RUA-PROM/mac-healh-keeper/rulesets/{id} \
  -f enforcement=disabled

# 完全削除（最終手段）
gh api -X DELETE repos/RUA-PROM/mac-healh-keeper/rulesets/{id}
```

## 5. 緊急時運用

- **基本**: main の修正は常に feature branch + PR + CI 緑 + squash merge
- **障害時**:
  1. Ruleset を `enforcement: disabled` に切り替え（PATCH）
  2. 修正 commit を main へ push（最小限）
  3. Ruleset を `enforcement: active` に戻す
  4. memo / 04_review に経緯記録

bypass_actors を空のまま運用することで、「ADMIN だから無自覚にバイパスしてしまった」事故を構造的に防ぐ。
