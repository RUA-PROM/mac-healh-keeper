# 仕様更新ルール

仕様と実装は常に同期させる。

---

## 基本ルール

- 実装変更 → docs 更新
- 仕様変更 → 実装更新

---

## docs の役割

docs は **現在の仕様の一次情報**とする。

---

## 更新対象

以下の場合 docs を更新する。

- API変更
- 画面仕様変更
- データ構造変更
- ユースケース変更

---

## アプリバージョンの正本

issue: 20260529_105524_ビルド時バージョン自動stamp（v1.3.0〜）で `CFBundleVersion` / `CFBundleShortVersionString` の役割を分離した。

- **`CFBundleShortVersionString` がユーザー向けバージョンの正本（手動 semver）**。`src/Info.plist` に即値で記載する。macOS About アラート / docs / README のバージョン表記はすべてこのキーに追従する。
- **`CFBundleVersion` はビルド識別子で、`install.sh` 経由で `scripts/lib/version_stamp.sh` が `git -C "$REPO_DIR" describe --tags --always` を `plutil -replace` で注入する従属情報**。手動更新しないこと。リポジトリの `src/Info.plist` 上はテンプレ値 `0.0.0-DEV` を保持し、stamp 失敗時の検知容易性を確保する。
- `docs/` 配下や `README.md` のバージョン記載（例: `docs/02_画面設計/README.md::G012` の `バージョン` 表記、`docs/01_システム概要/04_ディレクトリ構成/README.md` の `CFBundleShortVersionString=X.Y` 注記）は、`CFBundleShortVersionString` に追従する従属情報である。
- Swift コード上の About アラート文言（`src/MacHealth.swift::showAbout`）は `Bundle.main.infoDictionary["CFBundleShortVersionString"]` から動的取得するため、コードリテラルの追従更新は不要（`formatAboutVersionLine` 純粋関数経由・取得失敗時は `"バージョン 不明"` にフォールバック）。
- `CFBundleShortVersionString` の形式は **2 桁（`X.Y`）** を採用（既存履歴 `1.0` → `1.2` → `1.3` に倣う）。仕様書（`docs/`）の `vX.Y.Z` 形式とは別概念であり、両者は同時に bump されるとは限らない。

## バージョン更新時の必須手順

機能追加・修正でユーザー向けバージョンを bump する場合、以下の順で実施する。

1. `src/Info.plist` の **`CFBundleShortVersionString`** のみを更新（**正本の更新**）。
   - **`CFBundleVersion` は手動更新しない**（`install.sh` 経由で `git describe --tags --always` の値が `plutil -replace` で注入される）。テンプレ値 `0.0.0-DEV` のままにしておく。
2. About アラート文言（`src/MacHealth.swift::showAbout`）は **Bundle 動的取得により自動追従するため手動更新不要**。`Bundle.main.infoDictionary["CFBundleShortVersionString"]` から `formatAboutVersionLine` 経由で参照しており、`CFBundleShortVersionString` の値変更にそのまま追従する。
3. 連動する docs を追従更新する。
   - `docs/02_画面設計/README.md::G012` の `informativeText` 表記（リテラル `バージョン X.Y` を実装と整合させる。動的取得である旨も併記）。
   - `docs/01_システム概要/04_ディレクトリ構成/README.md` の `src/Info.plist` 行の `CFBundleShortVersionString=X.Y` 注記。
   - 他にも `grep -rn "バージョン X\.Y"` `grep -rn "CFBundleShortVersionString"` で網羅確認すること。
4. 仕様書バージョン（`docs/README.md::更新履歴` の `vX.Y.Z`）と各 README 末尾の「最終更新」を必要に応じて更新する（仕様書バージョンと Info.plist バージョンは独立の概念）。
5. リリース記録を `docs/00_review/` に作成する。
