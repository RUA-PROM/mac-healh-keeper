# 仕様更新ルール

仕様と実装は常に同期させる。

---

## 基本ルール

- 実装変更 → docs 更新
- 仕様変更 → 実装更新

---

## docs の役割

docs は **現在の仕様の一次情報**とする。

---

## 更新対象

以下の場合 docs を更新する。

- API変更
- 画面仕様変更
- データ構造変更
- ユースケース変更

---

## アプリバージョンの正本

- **アプリバージョンの正本は `src/Info.plist` の `CFBundleVersion` / `CFBundleShortVersionString` とする**。macOS アプリの仕様上、これがランタイムから参照されるバージョンの一次情報である。
- `docs/` 配下や `README.md` のバージョン記載（例: `docs/02_画面設計/README.md::G012` の `バージョン X.Y` リテラル、`docs/01_システム概要/04_ディレクトリ構成/README.md` の `CFBundleVersion=X.Y` 注記）は、Info.plist に**追従する従属情報**である。
- Swift コード上の About アラート文言（`src/MacHealth.swift::showAbout`）も Info.plist と同じ値とする。
- バージョン形式は **2 桁（`X.Y`）** を採用（既存履歴 `1.0` → `1.2` → `1.3` に倣う）。仕様書（`docs/`）の `vX.Y.Z` 形式とは別概念であり、両者は同時に bump されるとは限らない。

## バージョン更新時の必須手順

機能追加・修正でバージョンを bump する場合、以下の順で実施する。

1. `src/Info.plist` の `CFBundleVersion` / `CFBundleShortVersionString` を更新（**正本の更新**）。
2. 連動するコードリテラルを追従更新する。
   - `src/MacHealth.swift::showAbout` の About アラート `informativeText` 内 `バージョン X.Y`。
3. 連動する docs を追従更新する。
   - `docs/02_画面設計/README.md::G012` の `informativeText` 表記。
   - `docs/01_システム概要/04_ディレクトリ構成/README.md` の `src/Info.plist` 行の `CFBundleVersion=X.Y` 注記。
   - 他にも `grep -rn "バージョン X\.Y"` `grep -rn "CFBundleVersion"` で網羅確認すること。
4. 仕様書バージョン（`docs/README.md::更新履歴` の `vX.Y.Z`）と各 README 末尾の「最終更新」を必要に応じて更新する（仕様書バージョンと Info.plist バージョンは独立の概念）。
5. リリース記録を `docs/00_review/` に作成する。
