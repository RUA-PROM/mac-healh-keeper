## 3. データ設計（03_データ設計）のレビュー

### 3.1. 指摘事項

#### 指摘事項 1: 絶対パスの混入 → 修正済み

**重要度**: 高

**問題**:

- `docs/03_データ設計/README.md` の rotate.err 例で `/Users/.../monitor.log.2` の表記を使用していた。`.agents/DOCS_RULES`（機密情報除外）に反する可能性。

**実装確認**:

```
log.sh::record_rotation_error は file 絶対パス を含めて記録するが、ユーザー個人のホームディレクトリは固有
```

**ドキュメント確認**:

```markdown
# docs/03_データ設計/README.md:178-179（修正前）
  [2026-05-28 03:00:42] [ERROR] [rotate] /Users/.../monitor.log.2: ...
  [2026-05-28 03:00:42] [ERROR] [rotate] /Users/.../launchd.refresh.out: ...
```

**対応方針**: `$HOME/Library/Logs/MacHealth/` 表記に置換済み。`grep -rn '/Users/' docs/` で再確認しマッチなし。

### 3.2. 確認済み項目

#### 確認済み項目 1: 値型のフィールドと既定値

**確認結果**: ✅ 整合性あり

**確認内容**: `Sources/MacHealthKit/Metrics.swift` の `MetricsSnapshot.init` 既定値（`"—"` / `[:]` / `.distantPast` 等）と `JobStatus`（loaded=false/lastRun=nil/nextRun=nil）を §3.2.1-§3.2.2 に転記。

#### 確認済み項目 2: 設定値（thresholds.sh）の既定値

**確認結果**: ✅ 整合性あり

**確認内容**: `scripts/config/thresholds.sh` 全行を読み §3.5 に転記。docker 業務時間内 cooldown 21600 秒がハードコードである旨を明記。

#### 確認済み項目 3: cooldown ファイル書式

**確認結果**: ✅ 整合性あり

**確認内容**: monitor は `notification_cooldown.sh::_should_notify_update` で `key:epoch` 行を `mv tmp file` で原子的に書込。docker は `check-docker.sh::COOLDOWN_FILE` で `echo "$now" > <file>`（key なし）。差異を §3.3.6 に明記。

## 5. エラー処理と外部通知（05_エラー処理と外部通知）のレビュー

### 5.1. 指摘事項

#### 指摘事項 1: HTTP サーバを持たないテンプレからの逸脱

**重要度**: 中（仕様）

**問題**:

- テンプレ `.workflow/templates/docs/05_エラー処理と外部通知/README.md` は HTTP サーバ向け（汎用 Exception ハンドラ・ミドルウェア二重防止・error.code マッピング表）を前提とする。本プロジェクトは HTTP/RPC を持たないスタンドアロンアプリ + launchd バッチであり、テンプレ通りの内容は適用不可。

**実装確認**: `Sources/MacHealthKit/` および `scripts/` を全件読み、HTTP ハンドラに相当する箇所が存在しないことを確認。

**対応方針**: テンプレの骨子（共通化・二重防止・記録・観測点）は維持しつつ、本プロジェクト固有のエラー分類（ローテート失敗・ロック取得失敗・ジョブ起動失敗・通知失敗・ShellRunner 失敗・docker タイムアウト・Quit 失敗・install/uninstall 部分失敗）に再構成。「観測しても止めない」方針と `events.log` の LEVEL（INFO/WARN/ACTION）を明文化。

### 5.2. 確認済み項目

#### 確認済み項目 1: rotate.err と stderr の二重記録

**確認結果**: ✅ 整合性あり

**確認内容**: `scripts/lib/log.sh::record_rotation_error` が stderr + `$LOG_DIR/rotate.err` の両方に書く実装と、`rotate.err` 自体の書込失敗を `|| true` で無視する実装を確認。

#### 確認済み項目 2: ロック取得失敗のベストエフォート方針

**確認結果**: ✅ 整合性あり

**確認内容**: `scripts/lib/lock.sh::with_lock` が `acquire_lock` 失敗時にロックなしで command を実行し、`record_rotation_error <name>.lock "lock acquisition failed; proceeding without lock"` を記録することを確認。
